Who I am

I am 21 and finishing an engineering degree in computer engineering and networks with a cybersecurity major at EMSI Casablanca (2022–2027). The course starts from the foundations — Linux and Windows Server systems, Active Directory, TCP/IP, DNS, TLS, VPN, virtualisation, programming — then specialises in security: cryptography, network security, vulnerability management and security monitoring.

Alongside the coursework, I mostly learn by building. I have set up a full Elastic Security SOC lab, a multi-VM Wazuh lab with Linux and Windows agents, and rounded out my training with three SOC-focused Splunk courses and Red Hat Linux administration (RH124). During my internships I automated Nmap scans in Python and ran GVM/OpenVAS vulnerability assessment campaigns at Nethash in Paris, after a first internship in full-stack web development at SIMDATA in Orléans — experience I now rely on to script and automate my own tooling.

What I genuinely enjoy about defensive security is the moment an attack becomes visible in the logs. Writing a detection rule forces you to understand an attacker's behaviour precisely, not just the tool they happen to use: which events it generates, what separates it from legitimate activity, and where the threshold for raising an alert actually sits. I like what comes next just as much — triage, investigation, cutting down false positives, and writing the documentation that lets someone else retrace the investigation. That is the work of a SOC, and it is the work I want to do.

Elastic Security SOC lab

Personal project · 2026
Context

I wanted to practise detection on my own data rather than on prepared log datasets. So I built a complete SOC in the lab — collection, rules, investigation — then ran real attacks against Linux and Windows machines to write and stress-test the matching detections.

What I did
  • Deployed the Elasticsearch + Kibana stack with Fleet, and enrolled Elastic Agents on Ubuntu, Windows 11 and a Windows Server domain controller.
  • Instrumented the Windows hosts with Sysmon and enabled PowerShell Script Block Logging to capture the events the detections depend on.
  • Wrote and validated 4 detection rules across 3 attack scenarios, each one triggered by a simulated attack and then tuned to limit false positives.
  • Wrote an investigation guide for every rule: what the alert means, which fields to check first, and the triage steps to follow.
  • Documented the whole lab on GitHub so that it can be reproduced.
The 3 detection scenarios

  • SSH brute force (Linux)

    Detects repeated authentication failures from a single source, then correlates the sequence "multiple failures followed by a successful login" in EQL — the signal that separates an attempt from a likely compromise.

  • Obfuscated PowerShell (Windows 11)

    Detects base64-encoded commands passed to PowerShell, using the script blocks captured by Script Block Logging.

    MITRE ATT&CK T1059.001

  • Active Directory password spray (Windows Server)

    A KQL threshold rule on Event ID 4625 from the domain controller, aggregated by source.ip with a cardinality condition on user.name: that condition is what distinguishes a password spray — many accounts tried, few attempts on each — from a classic brute force against a single account.

    MITRE ATT&CK T1110.003
