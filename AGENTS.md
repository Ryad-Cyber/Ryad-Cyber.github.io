# Portfolio — règles permanentes

- Conserver le design actuel bleu nuit / bleu électrique et ses animations ; faire des ajustements ciblés.
- Positionnement : élève ingénieur en cybersécurité orienté Cloud Security (objectif principal), puis SOC et Pentest ; ne jamais revendiquer un titre de poste (pas d'animation de métiers).
- Garder les projets fidèles à ce qui a été réalisé : ne pas requalifier un projet SOC ou Pentest en projet Cloud.
- Concevoir un design original et professionnel, sans apparence de template IA.
- Conserver les typographies du nom : Source Sans 3 dans la bannière, Barlow Condensed sur l’accueil.
- Marque sans cadre RB, photo rectangulaire respectant son cadrage d’origine.
- Projets en grille compacte régulière (2–3 colonnes sur ordinateur), sans carte vedette ; catégories lisibles.
- Bloc Programmation synthétique ; ne pas réintroduire le paragraphe générique « Mon approche ».
- Décrire les compétences de façon générale et exacte ; garder les détails chiffrés dans les expériences et études de cas.
- Contact direct et mini-formulaire mailto honnête : brouillon dans la messagerie, aucun envoi depuis le site.
- Maintenir la cohérence des six pages françaises et anglaises.
- Ne jamais inventer d’expériences, compétences, certifications ou réalisations.
- Préserver les sept projets, leurs descriptions techniques, captures et fonctionnalités utiles.
- Inclure chaque image de couverture dans la galerie du cas détaillé, une seule fois.
- Respecter le responsive, le clavier, les contrastes et les préférences de mouvement réduit.
- Éviter les dépendances inutiles ; conserver la compatibilité GitHub Pages.
- Ne pas modifier les CV.
- Vérifier les liens, les interactions et le rendu mobile / ordinateur avant de terminer.
- Ne jamais effectuer de commit ou push sans demande explicite de l’utilisateur.
