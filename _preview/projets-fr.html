CAS Nº1 — Lab SOC Elastic Security

2026 Projet personnel Elasticsearch, Kibana, Elastic Security, Fleet, Elastic Agent, Sysmon, KQL, EQL, MITRE ATT&CK, Windows Server / AD, Ubuntu

Objectif

Développer un environnement de détection sur mes propres machines virtuelles afin de comprendre le fonctionnement d'une chaîne de détection : collecte des journaux, création de règles, génération d'alertes et investigation. J'ai testé les détections à l'aide d'attaques simulées sur des systèmes Linux et Windows, plutôt que de m'appuyer uniquement sur des jeux de journaux préconstruits.

Mise en œuvre

  1. Déployé Elasticsearch et Kibana, configuré Fleet et enrôlé des Elastic Agents sur Ubuntu, Windows 11 et un contrôleur de domaine Windows Server.
  2. Configuré Sysmon et activé le Script Block Logging de PowerShell sur Windows pour collecter les événements utiles à l'investigation.
  3. Créé et testé 4 règles de détection couvrant 3 scénarios d'attaque, puis ajusté leur logique afin de limiter les faux positifs observés pendant les tests.
  4. Rédigé des guides d'investigation précisant la signification des alertes, les champs à examiner et les étapes de qualification.
  5. Documenté la configuration et les règles dans un dépôt GitHub public.

Scénarios de détection

  • SSH Brute Force — Linux

    Détection d'échecs d'authentification répétés provenant d'une même source. Une séquence EQL permet également de repérer plusieurs échecs suivis d'une connexion réussie, un signal qui mérite une investigation plus poussée.

  • PowerShell obfusqué — Windows 11
    MITRE ATT&CK T1059.001

    Détection de commandes PowerShell utilisant un contenu encodé en Base64, à partir des événements collectés grâce au Script Block Logging.

  • Password spraying — Active Directory
    MITRE ATT&CK T1110.003

    Règle de type Threshold en KQL basée sur l'événement Windows 4625 du contrôleur de domaine. Les événements sont regroupés par source.ip, avec une cardinalité sur user.name, afin de repérer une source testant plusieurs comptes avec un nombre limité de tentatives par compte.

Consulter le dépôt GitHub — règles et guides d'investigation

CAS Nº2 — Lab Wazuh SIEM multi-VM

05/2026 Projet académique Wazuh, VMware, Linux, Windows, MITRE ATT&CK, Nmap, Syslog

Objectif

Déployer un SIEM open source sur plusieurs machines virtuelles Linux et Windows, puis vérifier que les événements collectés permettent de détecter des activités suspectes et de générer des alertes exploitables.

Mise en œuvre

  1. Installé le manager Wazuh et déployé des agents sur des machines Linux et Windows pour centraliser les journaux.
  2. Créé 2 règles de détection personnalisées associées à des techniques MITRE ATT&CK.
  3. Testé les règles avec des scénarios simulés de brute force SSH et de reconnaissance réseau avec Nmap, puis vérifié la remontée des alertes dans le tableau de bord.
  4. Comparé les résultats de Wazuh avec ceux d'Elastic Security sur des scénarios équivalents afin d'étudier les différences entre les deux solutions.

Projet académique — documentation non publiée.

CAS Nº3 — KASBAH 2026 — gestion de crise cyber

09/2026 EMSI × CyberSup

Contexte

Exercice de gestion de crise cyber sur trois jours, simulant une attaque contre une organisation. Les participants devaient analyser une situation évolutive, prendre des décisions avec des informations partielles et coordonner leur réponse.

Mon rôle

  • Participation à la cellule Direction et contribution aux arbitrages pendant la crise.
  • Prise en compte de l'équilibre entre les mesures de confinement et la continuité d'activité.
  • Coordination et communication avec les cellules techniques et les interlocuteurs concernés.
  • Travail sur la prise de décision et la transmission claire des informations dans un contexte d'incertitude.

Compétences mobilisées

  • Gestion de crise
  • Coordination
  • Prise de décision
  • Communication
  • Travail en équipe
