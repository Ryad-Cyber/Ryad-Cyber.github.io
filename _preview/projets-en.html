CASE Nº1 — Elastic Security SOC Lab

2026 Personal project Elasticsearch, Kibana, Elastic Security, Fleet, Elastic Agent, Sysmon, KQL, EQL, MITRE ATT&CK, Windows Server / AD, Ubuntu

Objective

Build a detection environment using my own virtual machines to understand the detection workflow: log collection, rule creation, alert generation and investigation. I tested the detections using simulated attacks against Linux and Windows systems rather than relying solely on pre-built log datasets.

Implementation

  1. Deployed Elasticsearch and Kibana, configured Fleet, and enrolled Elastic Agents on Ubuntu, Windows 11 and a Windows Server domain controller.
  2. Configured Sysmon and enabled PowerShell Script Block Logging on Windows to collect events relevant to detection and investigation.
  3. Created and tested 4 detection rules covering 3 attack scenarios, then refined their logic to reduce false positives observed during testing.
  4. Wrote investigation guides explaining what each alert means, which fields to examine and how to assess the activity.
  5. Documented the configuration and detection rules in a public GitHub repository.

Detection scenarios

  • SSH Brute Force — Linux

    Detects repeated authentication failures from a single source. An EQL sequence also identifies multiple failures followed by a successful login, a signal that warrants further investigation.

  • Obfuscated PowerShell — Windows 11
    MITRE ATT&CK T1059.001

    Detects PowerShell commands containing Base64-encoded content using events collected through Script Block Logging.

  • Active Directory Password Spraying
    MITRE ATT&CK T1110.003

    A KQL threshold rule based on Windows Event ID 4625 from the domain controller. Events are grouped by source.ip, with a cardinality condition on user.name, to identify a source attempting authentication against multiple accounts with relatively few attempts per account.

View the GitHub repository — detection rules and investigation guides

CASE Nº2 — Multi-VM Wazuh SIEM Lab

May 2026 Academic project Wazuh, VMware, Linux, Windows, MITRE ATT&CK, Nmap, Syslog

Objective

Deploy an open-source SIEM across multiple Linux and Windows virtual machines, then verify that collected events can be used to detect suspicious activity and generate actionable alerts.

Implementation

  1. Installed the Wazuh manager and deployed agents on Linux and Windows machines to centralise log collection.
  2. Created 2 custom detection rules mapped to MITRE ATT&CK techniques.
  3. Tested the rules using simulated SSH brute-force activity and network reconnaissance with Nmap, then verified that alerts appeared in the dashboard.
  4. Compared Wazuh with Elastic Security using equivalent scenarios to examine differences between the two solutions.

Academic project — documentation not publicly available.
