CAS Nº1 — Elastic Security SOC lab

2026 Personal project Elasticsearch, Kibana, Elastic Security, Fleet, Elastic Agent, Sysmon, KQL, EQL, MITRE ATT&CK, Windows Server / AD, Ubuntu

Context

I wanted to practise detection on my own data rather than on prepared log datasets. So I built a complete SOC in the lab — collection, rules, investigation — then ran real attacks against Linux and Windows machines to write and stress-test the matching detections.

What I did

  1. Deployed the Elasticsearch + Kibana stack with Fleet, and enrolled Elastic Agents on Ubuntu, Windows 11 and a Windows Server domain controller.
  2. Instrumented the Windows hosts with Sysmon and enabled PowerShell Script Block Logging to capture the events the detections depend on.
  3. Wrote and validated 4 detection rules across 3 attack scenarios, each one triggered by a simulated attack and then tuned to limit false positives.
  4. Wrote an investigation guide for every rule: what the alert means, which fields to check first, and the triage steps to follow.
  5. Documented the whole lab on GitHub so that it can be reproduced.

The 3 detection scenarios

  • SSH brute force (Linux)

    Detects repeated authentication failures from a single source, then correlates the sequence "multiple failures followed by a successful login" in EQL — the signal that separates an attempt from a likely compromise.

  • Obfuscated PowerShell (Windows 11)
    MITRE ATT&CK T1059.001

    Detects base64-encoded commands passed to PowerShell, using the script blocks captured by Script Block Logging.

  • Active Directory password spray (Windows Server)
    MITRE ATT&CK T1110.003

    A KQL threshold rule on Event ID 4625 from the domain controller, aggregated by source.ip with a cardinality condition on user.name: that condition is what distinguishes a password spray — many accounts tried, few attempts on each — from a classic brute force against a single account.

GitHub repository — rules and investigation guides

CAS Nº2 — Multi-VM Wazuh (SIEM) lab

05/2026 Academic project Wazuh, VMware, Linux, Windows, MITRE ATT&CK, Nmap, Syslog

Context

Deploy an open-source SIEM across a mixed infrastructure of several virtual machines, and verify end to end that it actually detects attacks — not merely that it collects logs.

What I did

  1. Installed the Wazuh manager and deployed agents on Linux and Windows machines, with centralised log collection.
  2. Wrote 2 custom detection rules, mapped to the MITRE ATT&CK framework.
  3. Validated each rule with simulated attacks — SSH brute force and Nmap scans — and confirmed the alerts surfaced in the dashboard.
  4. Compared how Wazuh and Elastic Security behave on equivalent scenarios, to understand what each tool makes easy or hard.

Academic project — internal documentation, repository not public.
